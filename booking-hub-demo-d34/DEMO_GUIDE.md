## 🎬 시연 플로우 (7분)

### Scene 1: 판정 1 - 빈 칸 검증 (2분)

**화면**: "예약" 탭 → "예약추가" 폼

**시나리오**:
1. 고객사 칸을 의도적으로 비운다 (다른 칸은 채움)
2. "예약 추가" 버튼 상태 관찰
   - 파랑(ask) + 버튼 비활성화 (잠김) → "빈 칸이 있으면 저장 못 합니다"
3. 고객사 칸에 입력 (예: "SK하이닉스")
4. 버튼이 초록(book) + 활성화 → "이제 저장할 수 있습니다"

**말**:
> "프롬프트 1: 빈 칸 검증. 고객사가 없으면 예약을 저장할 수 없습니다. 파랑은 물어보는 것, 초록은 책임있게 진행하는 것. 칸을 채우면 초록으로 바뀝니다."

---

### Scene 2: 판정 2 - 자동 판정 + Realtime 대시보드 (5분)

**화면 설정**: 브라우저 2개 나란히 배치
- **왼쪽**: "상태" 탭 (대시보드)
- **오른쪽**: "예약" 탭 (목록)

**Step 1**: 예약 4줄 넣기

오른쪽 예약 폼에서 아래 4개를 순서대로 입력 (날짜는 2026-09-08, 09-10):

```
【대조 카드 가】
- 고객사: 삼성전자
- 서비스: 컨설팅  
- 날짜: 2026-09-08
- 시간: 09:00
- 위치: 강남역

【대조 카드 나】
- 고객사: LG디스플레이
- 서비스: 교육
- 날짜: 2026-09-08
- 시간: 10:00
- 위치: 강남역

【대조 카드 다】
- 고객사: 네이버
- 서비스: 기술지원
- 날짜: 2026-09-10
- 시간: 14:00
- 위치: 서울역

【대조 카드 라】
- 고객사: 카카오
- 서비스: 운영
- 날짜: 2026-09-08
- 시간: 11:00
- 위치: 판교
```

**Step 2**: 줄마다 판정 버튼 클릭

각 예약 줄의 "판정" 버튼을 하나씩 클릭하면서 결과 관찰:

| 예약 | 예상 판정 | 색상 | 의미 |
|------|---------|------|------|
| 가 | blocked | 🔴 빨강 | 일반인 확정 (시간 맞는데 같은 자리에 이미 있음) |
| 나 | auto | 🟢 초록 | 자동 확정 (시간/장소 OK) |
| 다 | asking | 🔵 파랑 | 물어보기 (시간 정보 부족) |
| 라 | needs_human | 🟡 노랑 | 사람 판단 (옵션 목록 있음) |

**Step 3**: 왼쪽 대시보드 자동 갱신

각 판정 버튼을 클릭할 때마다 왼쪽 대시보드 카드들이 자동으로 움직입니다:
- pending → 판정됨
- 새로고침 없이 Realtime으로 갱신

**Step 4**: "전부 판정" 버튼

모든 예약 판정 후, 상태 탭의 "전부 판정" 버튼 클릭 → pending 카드 비워짐

**말**:
> "프롬프트 2, 3, 4: 자동 판정. 
> 
> 각 예약마다 규칙대로 판정합니다:
> - 초록(auto): 시간/장소/사람 확인돼서 자동으로 확정
> - 노랑(needs_human): 같은 시간 같은 곳에 여럿이 있으면 보조 위치 옵션을 보여줍니다. 사람이 고릅니다
> - 빨강(blocked): 일반인 확정이 이미 있으면 못 들어갑니다
> - 파랑(asking): 시간 정보가 없으면 물어봅니다
>
> 그리고 이 대시보드는 새로고침 없이 Realtime으로 갱신됩니다."

## 🔧 만약 깨진다면?

| 증상 | 해결법 |
|------|--------|
| "연결할 수 없음" 에러 | SQL 초기화 안 됨 → `sql_init.md` 다시 확인 |
| 왼쪽 대시보드가 안 움직임 | Realtime 설정 안 됨 → `20_리얼타임_켜기.sql` 다시 실행 |
| 브라우저에 아무것도 안 보임 | `npm run dev` 다시 실행 후 F5 새로고침 |
| 콘솔에 TypeScript 에러 | 이미 build 됐으므로 무시 (런타임에는 영향 없음) |
